### What mon is

- A single-package rewrite (3.0) of the 2.x monorepo. It is pre-alpha and is
  being ported from `mon_old` one module at a time. Python >= 3.13, torch >=
  2.15, uv, MIT.
- Layering (checked by tests/test_namespaces.py): `core` imports nothing else
  from mon; `data`, `metrics` and `nn` import only core; `models` imports
  core and nn; `runners` imports anything. Every namespace exports lazily
  (`_EXPORTS` + literal `__all__`), so `import mon.core` doesn't load torch.
- core: paths ($DATA_DIR, $ZOO_DIR, $DATASETS_DIR, $RUNS_DIR), atomic file
  I/O and hashed downloads, OmegaConf configs with `_base_` inheritance,
  logging, AliasStrEnum, Registry (eager and lazy entries), devices (never a
  silent CPU fallback), seeding, Size, timing, Weights/WeightsEnum.
- data: OpenCV I/O, YOLO/VOC/COCO labels, FolderDataset (layout = split ->
  modalities, paired by stem), ClassFolderDataset, ImageFolder, seeded
  loaders, torchvision-v2 transforms (two stages; pad at inference, resize
  for training). 34 zoo ids:
  - LLE paired: lol_v1, lol_v2_real, lsrw_*, mit_5k, uhd_ll, sice*,
    loli_street, ntire_2025_llie.
  - LLE unpaired: dicm, fusion, lime, mef, npe, vv.
  - Detection: darkface, exdark, ydld, fisheye8k, widerface. Tracking:
    mot16, mot20. Segmentation: nightcity. Classification: cifar*, mnist*.
  - Testkit: lle, lle_unpaired, mef, classify, efficiency.
- models: 17 models in a lazy MODELS index.
  - LLE (14): zero_dce, zero_dce++, sgz, sci, sci++, ruas, pairlie,
    retinexnet, hvi_cidnet, dccnet, flol, clode, zero_ig, colie.
  - Denoise: tv_denoise, zs_n2n. MEF: mertens.
  - All have parity tests against official or mon_old outputs with released
    weights.
- nn: TrainRecipe, Zero-DCE zero-reference losses, Hann-window
  tiled_forward, complexity counting (FlopCounterMode), and small utils.
- metrics: psnr, ssim, lpips (full reference); niqe, brisque, nrqm, pi (no
  reference); all match pyiqa. Plus ranking (NTIRE 2025 LLIE composite).
- runners: `mon train | predict | evaluate | benchmark`.
  - Train is one loop with AMP, clipping, schedulers, validation, and exact
    resume.
  - Recipes exist for zero_dce, zero_dce++, sci, sci++ and zero_ig only.

### Findings (verified ones marked)

- Bug (verified): with the cosine scheduler, `resume=... epochs=<more>`
  keeps the old T_max. trainer.py:396 builds it from the new epochs, then
  :536 load_state_dict restores the old T_max. No scheduler tests.
- Bug (verified): evaluator.py:116 and benchmarker.py:290 divide by 255
  always; read_image returns uint16 for 16-bit PNG/TIFF.
- cli.py doesn't catch NotADirectoryError (predictor.py raises it), so the
  user gets a traceback.
- Evaluate stops on one bad image (e.g. too small for NIQE). The evaluator
  doesn't save config.yaml, and the benchmarker has no default run dir; both
  go against the runner convention.
- Convention gaps:
  - No url: CLODE, FLOL UHD_LL, HVI-CIDNet, RetinexNet weights.
  - Truncated source_sha256: hvi_cidnet.py:90-138.
  - Missing ClassVar annotation: ruas.py:430.
  - Duplicated losses: YCbCr smoothness in sci.py and zero_ig.py; the TV term
    in clode.py, zero_ig.py and colie.py; `_pair_downsample` in clode.py.
- Parity gaps:
  - HVICIDNetLoss, RetinexNetLoss and PairLIELoss are checked against
    written-out definitions, not reference copies of the official code.
  - No sgz_reference.py.
  - No loop-parity test for the sci, zero_dce++ and zero_ig recipes.
  - zero_ig is missing from the testkit regression.
