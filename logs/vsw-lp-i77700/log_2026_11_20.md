## 03:06 KST · vsw-lp-i77700 — Task 10: SCI++ recipe, SCI data notes

- `TrainRecipe` gains `optimizers` (named groups of submodules, one optimizer each, all from `optimizer`) and
  `schedule(step) -> name | None`; the step returns `loss_<name>` per optimizer. The trainer sets `requires_grad`
  per group, clips only the active group, keeps one scheduler per optimizer, and checkpoints
  `{"optimizer": {name: state}}` for such recipes (single-optimizer checkpoints unchanged).
- `SCIPP_RECIPE` (`sci++`, official `TPAMI/train.py` at `f6f88fd`): Adam 3e-4 / wd 3e-4 for `ha` and for `hb` +
  `calibrate`, batch 1, file order, 3000 epochs, seed 2, no init, no clip (the official clip runs after the step).
  The official loop toggles `requires_grad` after the forward, so the first step of each phase updates nothing
  (verified with torch 2.15): effective schedule `ha` at steps ≡ 1–6 (mod 10), `hb` at ≡ 8, 9. Parity test vs the
  literal official loop: max |Δ| < 1e-6 (the literal 7/3 schedule is off by 2.6e-3). `weights_1_3500` = epoch 1,
  step 3500 → 1750–3499 training images; the README names no set.
- `SCI_RECIPE` docstring: released weights by data (easy → `mit_5k`, medium → `lol_v1` / `lsrw_*`, difficult →
  `darkface`; "mainly", no lists, not exactly reproducible); the paper uses the authors' 500 MIT / 500 LSRW subsets
  (Google Drive, not in `mon`). `mon_old` configs (512 px, batch 8, lr 1e-4) are not the official recipe.
- Smoke run `sci++` on `lol_v1` (GPU, 2 epochs): both objectives fall; 11.5 s/epoch (3000 epochs ≈ 9.6 h).
