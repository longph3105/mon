## Switch to headless OpenCV

- `opencv-python` → `opencv-python-headless>=5.0` (5.0.0.93). Relocked and synced.
- Checked GUI support: the macOS arm64 headless wheel still has `GUI: COCOA` (`imshow` works);
  the Linux x86_64 wheel has `GUI: NONE` (`imshow`/`waitKey` raise `cv2.error`), even on a desktop with a display.

## OpenCV as `gui` / `headless` extras

- Moved OpenCV out of base deps into `[project.optional-dependencies]`: `gui = opencv-python>=5.0`,
  `headless = opencv-python-headless>=5.0`; declared them as `tool.uv.conflicts` (both install `cv2/`).
- Verified: `--extra gui --extra headless` is rejected; switching extras swaps the package cleanly.
  `.venv` now synced with `--extra gui` (`GUI: COCOA`).
- Caveat: a bare `uv sync` removes OpenCV; `pip install mon` without an extra has no `cv2`.

## OpenCV: headless by default

- Tried "headless by default, GUI build with `[gui]`": not expressible. Base deps always install, extras only add,
  and `extra != 'gui'` markers in base deps / uv overrides still install both builds (tested with uv and pip).
  Dependency groups + `default-groups` work only until the next `uv run`/`uv add` re-adds headless. PEP 771
  (default extras) would solve it but is a draft.
- Final: `opencv-python-headless>=5.0` in base deps; `gui` extra = `matplotlib>=3.11` for display.
  Removed the `headless` extra and `tool.uv.conflicts`. Relocked; `uv sync` and `uv sync --extra gui` verified.

## PyQt6 → PySide6-Essentials

- `gui` extra: replaced `PyQt6` (GPL) with `PySide6-Essentials>=6.12` (LGPL, official Qt bindings).
  Chose Essentials over the `PySide6` meta-package: ~356 MB vs ~1.3 GB (meta adds Addons + WebEngine).
- Relocked, synced `--extra gui`; verified `QApplication` import and matplotlib `QtAgg` on `PySide6`.
- Gotcha: switching an env from `PySide6` to `PySide6-Essentials` deletes the shared `PySide6/__init__.py`
  (`ImportError: cannot import name '__version__'`). Fixed with `uv sync --extra gui --reinstall-package pyside6-essentials`.

## Remove tabulate; compare omegaconf vs python-box

- Removed `tabulate` (rich covers tables). Relocked, synced.
- Tested `omegaconf` 2.4.0 vs `python-box` 8.0.1 side by side (temporary `uv run --with omegaconf`; not added).
  OmegaConf: interpolation + `oc.env`, dataclass schemas with type validation, `MISSING`, struct mode, dotlist CLI
  overrides; rejects non-primitive values (tensors). Box: dot access, deep merge, frozen, `default_box`, holds any
  object; no interpolation or validation. Decision pending.
